# vanilla-signal 1.1.3

发布日期：2026-08-08

## fix

### `bindList` / `For` keyed 列表精准局部更新

修复 keyed 列表在更新时会重新插入所有已存在 DOM 节点的问题。

旧实现虽然会通过 key 复用 record 和节点引用，但每次列表 effect 执行后都会对 `next` 中的所有记录执行 `parent.insertBefore(node, anchor)`。浏览器会把已存在节点的再次插入视为 DOM 移动，因此在 `MutationObserver` 中会表现为已有节点被 remove 后又 add。这会让 vanilla-jui 一类依赖局部 DOM 变更的组件误判列表发生了大范围结构变化。

新版本将列表项处理拆成两个阶段：

1. 创建新 record 时只执行 `renderItem` 并保存 `nodes`，不立即插入 DOM。
2. 完成 keyed diff 后，统一按目标顺序放置 record。
3. 放置时从右向左处理，以 `anchor` 或右侧已确认节点作为 cursor。
4. 每个 record 会先检查自己的节点是否已经连续位于 cursor 前方。
5. 只有节点不在正确位置时，才调用 `insertBefore`。

因此：

- 中间插入新 keyed item 时，只新增这个 item 对应的 DOM 节点。
- 尾部追加新 keyed item 时，只新增追加项节点。
- 删除 keyed item 时，只移除被删除项节点。
- 同 key 数据替换时，只更新 item signal，不触发 childList 增删。
- 排序变更仍保持 keyed DOM 节点身份复用，只移动位置不正确的记录。
- `For` 组件自动继承该修复，因为它内部继续通过 `bindList` 渲染列表。

保留行为：

- `bindList` 公共 API 不变。
- `For` 公共 API 不变。
- 默认 key 规则不变：对象优先使用 `id` / `key`，否则回退到索引。
- 重复 key 仍保留 warning：`[bindList] Duplicate key "..."`。
- fallback 渲染与清理逻辑保持不变。

### `queueTask` Promise warning

修复 `queueTask` 在 Promise fallback 分支中的 warning。

当运行环境不支持 `queueMicrotask` 时，内部会使用已解析 Promise 的 `then` 推入微任务队列。现在通过 `void resolvedPromise.then(fn)` 明确标记该 Promise 返回值不需要继续等待，消除 `no-floating-promises` warning，不改变运行行为。

## test

### 增加 keyed 列表 DOM mutation 精度测试

在 `tests/index.js` 中新增基于 `MutationObserver` 的测试辅助函数，用于直接观察列表容器的 `childList` 变更。

新增用例：

- `bindList keyed insert precision`
  - 初始列表为 `a, b, c`。
  - 更新为 `a, x, b, c`。
  - 断言最终 DOM 顺序为 `a, x, b, c`。
  - 断言 `addedNodes` 只包含 `x`。
  - 断言 `removedNodes` 为空。

- `bindList keyed data update precision`
  - 初始列表为 `a, b`。
  - 更新为同 key 的新数据 `a1, b1`。
  - 断言文本内容完成更新。
  - 断言没有新增 DOM 节点。
  - 断言没有移除 DOM 节点。

这两个用例覆盖了本次修复的核心目标：keyed 中间插入不影响已有节点，同 key 数据更新不触发结构变更。
